# Toolchain Setup — Git + Unity MCP Wiring

> **Date:** 2026-04-13
> **Scope:** Developer environment setup for Soulstream Matchmancer
> **Goal:** Version control the Unity project and connect Claude Code to the Unity Editor via MCP

---

## Problem Statement

Two toolchain gaps are blocking productive development:

1. **Git is scoped to the home directory.** A `.git` exists at `~/` with zero commits. Every file on the machine appears as untracked. The project has no version control.
2. **Unity MCP is half-wired.** The Coplay package (`com.coplaydev.unity-mcp` v9.6.7-beta.3) is installed in the Unity project via local path reference, and the Python server exists at `/Users/marknp/Downloads/unity-mcp-beta/Server/`. But Claude Code has no MCP server entry, so AI cannot communicate with the Unity Editor.

A third gap — no `CLAUDE.md` — means every Claude Code session starts without project context.

## Fix 1: Git — Scope the Repo to the Unity Project

### Current State
- `~/.git` exists, zero commits, tracks entire home directory
- No `.gitignore` anywhere in the project
- No version history for any Matchmancer code

### Actions

**Step 1 — Remove the home-level `.git`**

Delete `~/.git`. This is safe because:
- It has zero commits (verified via `git log`)
- No staged or committed data exists
- It is actively harmful (makes `git status` unusable from any subdirectory)

**Step 2 — Initialize a proper repo**

Run `git init` inside `/Users/marknp/Final Work/Match Mancer/SoulstreamMatchmancer/`.

This scopes version control to the actual Unity project, which contains:
- `Assets/Scripts/` — all gameplay code (~95 C# files across 15+ systems)
- `Assets/Tests/` — 39 EditMode test files
- `Assets/Data/` — ScriptableObject assets (CombatConfig, DefaultCharacter, Stage1_Enemy)
- `Assets/Scenes/` — BattleScene.unity
- `Assets/Prefabs/` — Tile, StoneBlock, DamagePopup prefabs
- `Assets/Editor/` — editor scripts
- `Packages/manifest.json` — package dependencies
- `ProjectSettings/` — Unity project configuration
- `Skills/` — Claude skill files for the project
- `docs/` — design specs

**Step 3 — Add a Unity `.gitignore`**

Standard Unity gitignore covering:
- `Library/` — Unity's local cache (regenerated on open)
- `Temp/` — temporary build files
- `Logs/` — editor log files
- `UserSettings/` — local editor preferences
- `obj/` — .NET build intermediates
- `Builds/` — output builds
- `*.csproj`, `*.sln`, `*.slnx` — IDE-generated project files (regenerated by Unity)
- `.DS_Store`, `.DS_Store?`, `._*`, `.Spotlight-V100`, `.Trashes` — macOS metadata
- `.idea/`, `.vscode/`, `*.swp`, `*.swo` — IDE-specific config

**Step 3b — Set up Git LFS**

Unity projects inevitably accumulate binary assets. Set up LFS before the first commit to avoid repo bloat:
1. Run `git lfs install` in the repo
2. Create `.gitattributes` tracking common Unity binary types: `*.png`, `*.psd`, `*.jpg`, `*.wav`, `*.mp3`, `*.fbx`, `*.obj`, `*.ttf`, `*.otf`, `*.asset` (binary-serialized), `*.unity` (scenes can be large)

This ensures binary files are stored via LFS from the start, rather than having to migrate later.

**Step 4 — Initial commit**

Stage all project files and commit:
```
Initial commit — Soulstream Matchmancer project

Core systems: Board, Match, Combat, Characters, Gear, Enemies,
Progression, Achievements, Boosters, Shop, Save, UI, Story.
39 EditMode tests. BattleScene + prefabs.
```

### What Stays Outside the Repo

These folders are in the parent `Match Mancer/` directory but NOT inside `SoulstreamMatchmancer/`:
- `Matchmancer/` — standalone code-only copy (duplicate of Scripts)
- `Art Department/`, `Hero Characters/`, `Poster Mixed/`, `VIP VID/` — art assets
- `Production Bible/`, `Book/` — design documents
- `*.mp3`, `*.docx`, `*.xlsx` — media and office files

These can be added later or tracked in a separate repo if needed. The Unity project is the priority.

## Fix 2: Unity MCP — Wire Coplay to Claude Code

### Current State
- Unity side: `com.coplaydev.unity-mcp` v9.6.7-beta.3 installed via `file:/Users/marknp/Downloads/unity-mcp-beta/MCPForUnity`
- Python server: exists at `/Users/marknp/Downloads/unity-mcp-beta/Server/` with `pyproject.toml` (package name: `mcpforunityserver`)
- `uv` v0.11.6 and Python 3.13.7 are installed
- Claude Code settings (`~/.claude/settings.local.json`) have permission rules but NO `mcpServers` entry

### Actions

**Step 1 — Add MCP server config to Claude Code**

Merge into `~/.claude/settings.local.json`, preserving the existing `permissions` key:
```json
{
  "permissions": { ... existing permissions ... },
  "mcpServers": {
    "unity-mcp": {
      "command": "uvx",
      "args": ["--from", "mcpforunityserver", "mcp-for-unity"]
    }
  }
}
```

This uses the published `uvx` approach from Coplay's manifest. `uvx` will download and cache the server package automatically. The existing `permissions` block must not be removed or overwritten.

**Fallback if PyPI package not found:** The beta may not be published to PyPI. If `uvx` fails to resolve `mcpforunityserver`, use the local path instead:
```json
"args": ["--from", "/Users/marknp/Downloads/unity-mcp-beta/Server", "mcp-for-unity"]
```

**Step 2 — Verify connection**

After restarting Claude Code:
1. Unity must be open with the SoulstreamMatchmancer project loaded
2. The Coplay plugin must be running in the Unity Editor (check the MCP for Unity window)
3. Claude Code should show Unity MCP tools available (e.g., `manage_gameobject`, `read_console`, `run_tests`)

### Prerequisite
Unity Editor must be running with the project open for the WebSocket bridge to connect. If Unity is closed, MCP tools will fail gracefully.
